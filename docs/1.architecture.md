# TodoList Application Architecture

## Overview
This is a modern .NET 9 Blazor Server application with a clean, monolithic architecture suitable for Azure Container Apps deployment. The application follows best practices for cloud-native development with PostgreSQL as the primary database and SQLite as a fallback for development.

## Technology Stack

### Backend Framework
- **ASP.NET Core 9.0** - Web framework with Blazor Server components
- **Entity Framework Core 9.0** - ORM for database operations
- **PostgreSQL** (primary) with **SQLite** fallback for local development

### Frontend
- **Blazor Server** - Interactive server-side UI with real-time updates
- **Custom CSS** - Component-specific styling
- **Responsive Design** - Mobile-first approach

### Database
- **PostgreSQL 15** (production) - Configured with connection pooling and retry policies
- **SQLite** (development/fallback) - Local development database
- **Entity Framework Core** with migrations support

### Additional Features
- **Health Checks** - Database and self-health monitoring
- **Application Insights** - Telemetry and monitoring (production only)
- **CORS Support** - For MCP client integration
- **Structured Logging** - Comprehensive logging with correlation IDs
- **MCP Protocol Support** - AI assistant integration with JSON-RPC 2.0

## Architecture Pattern

### Monolithic Architecture
This is a **single-service monolithic application** with the following layers:

1. **Presentation Layer**: Blazor Server components and pages
2. **Service Layer**: Business logic in `TodoListService`
3. **Data Layer**: Entity Framework Core with `TodoDbContext`
4. **Models**: Domain entities (`TodoItem`)

### Project Structure
```
TodoList/
├── Components/              # Blazor UI components
│   ├── Pages/              # Blazor pages (Todo.razor, Error.razor)
│   ├── Layout/             # Layout components
│   └── App.razor           # Root component
├── Models/                 # Domain entities
│   └── TodoItem.cs         # Todo item entity
├── Data/                   # Data access layer
│   └── TodoDbContext.cs    # EF Core context
├── Services/               # Business logic
│   └── TodoListService.cs  # Todo operations service
├── Tests/                  # Unit tests
│   └── TodoListServiceTests.cs
├── wwwroot/               # Static assets
├── Program.cs             # Application entry point
└── Dockerfile             # Container configuration
```

## Database Design

### TodoItem Entity
- **Id** (int, PK): Auto-increment primary key
- **Title** (string, 500 chars): Todo item description
- **IsDone** (bool): Completion status with default false
- **CreatedAt** (DateTime): Automatic timestamp
- **UpdatedAt** (DateTime): Last modification timestamp

### Connection Strategy
- Primary: PostgreSQL with connection string containing "Host="
- Fallback: SQLite for local development
- Retry policy: 3 attempts with 30-second max delay
- Health checks: Integrated EF Core health monitoring

## Containerization

### Docker Configuration
- **Base Image**: mcr.microsoft.com/dotnet/aspnet:9.0 (runtime)
- **Build Image**: mcr.microsoft.com/dotnet/sdk:9.0
- **Security**: Non-root user execution
- **Health Checks**: Curl-based endpoint monitoring
- **Port**: 8080 (HTTP)

### Docker Compose
- **PostgreSQL Service**: postgres:15 with persistent volume
- **Application Service**: Multi-stage build with health checks
- **Networking**: Custom bridge network for service communication
- **Data Persistence**: Named volume for PostgreSQL data

## Deployment Target

### Azure Container Apps (Recommended)
- **Single Container**: One app instance for the monolithic architecture
- **Database**: Azure PostgreSQL Flexible Server
- **Secrets**: Azure Key Vault integration
- **Scaling**: Automatic based on HTTP traffic
- **Ingress**: External HTTPS with custom domain support

### Resource Dependencies
1. **Resource Group**: Container for all resources
2. **Azure Container Registry**: Store application images
3. **Azure PostgreSQL**: Managed database service
4. **Azure Key Vault**: Secure secret management
5. **Log Analytics Workspace**: Centralized logging
6. **Application Insights**: Application monitoring
7. **Azure Container Apps Environment**: Hosting environment
8. **Azure Container App**: Application instance

## Security Considerations
- **Managed Identity**: Service-to-service authentication
- **Key Vault**: Database connection strings and secrets
- **HTTPS Only**: Forced secure communication
- **Non-root Container**: Security-hardened container execution
- **CORS Policy**: Controlled cross-origin access

## Monitoring & Observability
- **Health Endpoints**: `/health` and `/health/ready`
- **Application Insights**: Performance and error tracking
- **Structured Logging**: JSON-formatted logs with correlation IDs
- **Database Health**: EF Core integrated health checks

## Testing Strategy
- **Unit Tests**: Service layer testing with xUnit
- **Integration Tests**: Database integration testing
- **Health Check Validation**: Endpoint monitoring
- **Container Testing**: Docker-based testing pipeline

## Scalability Considerations
- **Stateless Design**: Session state managed server-side (Blazor Server)
- **Database Connection Pooling**: Efficient database resource usage
- **Horizontal Scaling**: Container Apps auto-scaling
- **Static Asset Optimization**: Bundled and minified resources

This architecture supports efficient deployment to Azure Container Apps with a single container strategy, maintaining simplicity while providing production-ready scalability and monitoring capabilities.
