# TodoList Application Architecture

## Project Overview

The TodoList application is a modern ASP.NET Core 9.0 web application built with Blazor Server components and designed for cloud deployment. The application provides both a web interface and API endpoints for managing todo items, with integrated MCP (Model Context Protocol) support for AI tool compatibility.

## Technology Stack

### Core Framework
- **ASP.NET Core 9.0** - Web framework
- **Blazor Server** - Interactive UI components with server-side rendering
- **.NET 9** - Runtime platform
- **Entity Framework Core 9.0** - ORM for database operations

### Database
- **Primary**: PostgreSQL (Npgsql.EntityFrameworkCore.PostgreSQL 9.0.4)
- **Fallback**: SQLite (Microsoft.EntityFrameworkCore.Sqlite 9.0.6)
- **Auto-detection**: Application automatically selects PostgreSQL if connection string contains "Host=", otherwise falls back to SQLite

### Monitoring & Observability
- **Application Insights** (Microsoft.ApplicationInsights.AspNetCore 2.22.0)
- **Health Checks** (Microsoft.Extensions.Diagnostics.HealthChecks.EntityFrameworkCore 9.0.6)
- **Structured logging** with correlation IDs

### Containerization
- **Docker** support with multi-stage builds
- **Docker Compose** for local development with PostgreSQL
- **Health checks** integrated in containers
- **Non-root user** security model

## Architecture Pattern

### Single Service Monolith
The application follows a **single service monolith** pattern with clear separation of concerns:

```
├── Components/           # Blazor Server UI components
│   ├── Pages/           # Page components (Todo.razor)
│   └── Layout/          # Layout components
├── Services/            # Business logic layer (TodoListService)
├── Data/               # Data access layer (TodoDbContext)
├── Models/             # Domain models (TodoItem)
├── Tests/              # Unit tests
└── wwwroot/            # Static assets
```

### Key Components

1. **Presentation Layer**
   - Blazor Server pages with `@rendermode InteractiveServer`
   - Real-time UI updates with automatic refresh every 5 seconds
   - RESTful API endpoints for external integration
   - MCP protocol endpoints for AI tool integration

2. **Business Logic Layer**
   - `TodoListService` - Core business logic for todo operations
   - Async-first design with proper exception handling
   - CRUD operations: Create, Read, Update, Delete todo items

3. **Data Access Layer**
   - `TodoDbContext` - Entity Framework Core context
   - Automatic database creation and migration
   - Connection pooling and retry policies for PostgreSQL
   - Health checks for database connectivity

4. **Domain Models**
   - `TodoItem` - Core entity with Id, Title, IsDone properties
   - Data annotations for validation and database schema

## Deployment Architecture

### Container Strategy
- **Single Container**: One container for the entire monolithic application
- **Multi-stage Docker build** for optimized image size
- **Base Images**: 
  - Build stage: `mcr.microsoft.com/dotnet/sdk:9.0`
  - Runtime stage: `mcr.microsoft.com/dotnet/aspnet:9.0`

### Database Strategy
- **Separate Database Service**: PostgreSQL deployed as a separate Azure service
- **Connection Management**: Automatic failover to SQLite for development
- **Security**: Connection strings managed via Azure Key Vault

### Networking
- **Single Port**: Application serves both web UI and API on port 8080
- **Health Endpoints**: `/health` and `/health/ready` for monitoring
- **CORS**: Configured for MCP client access

## Infrastructure Requirements

### Azure Target Services
1. **Azure Container Apps (ACA)** - Primary hosting service
2. **Azure Container Registry (ACR)** - Container image storage
3. **Azure Database for PostgreSQL** - Managed database service
4. **Azure Key Vault** - Secret management
5. **Azure Virtual Network** - Network isolation
6. **Azure Monitor + Application Insights** - Observability
7. **Azure Log Analytics** - Centralized logging

### Resource Dependencies
- **Managed Identity** for secure access between services
- **Private endpoints** for database connectivity
- **Application Gateway** (optional) for advanced routing and security
- **Auto-scaling** based on CPU/memory metrics

## Security Considerations

### Authentication & Authorization
- Application currently has no built-in authentication
- Ready for integration with Azure AD or other identity providers
- Managed Identity used for Azure service-to-service communication

### Data Protection
- Database connection strings stored in Azure Key Vault
- No hardcoded secrets in application code
- User Secrets for local development (`UserSecretsId` configured)

### Network Security
- Container runs as non-root user
- Private endpoints for database connectivity
- CORS policies configured for controlled access

## Scalability Design

### Horizontal Scaling
- Stateless application design allows multiple instances
- Database connection pooling handles concurrent connections
- Blazor Server SignalR connections managed by Azure SignalR Service (when needed)

### Performance Optimizations
- Async-first approach throughout the application
- Entity Framework query optimization
- Health check endpoints for load balancer integration
- Minimal API endpoints for lightweight operations

## Development & Testing

### Local Development
- Docker Compose setup with PostgreSQL container
- Automatic database creation and seeding
- Hot reload support for development
- SQLite fallback for simplified local testing

### Testing Strategy
- Unit tests for `TodoListService`
- Integration tests planned for database operations
- Health check validation in containers
- CI/CD pipeline integration

## Deployment Considerations

### Idempotent Deployments
- Database migrations run automatically on startup
- Infrastructure as Code (Terraform) for repeatable deployments
- Blue-green deployment capability through container versioning

### Monitoring & Observability
- Application Insights integration for telemetry
- Health checks for service availability
- Structured logging with correlation tracking
- Performance counters and custom metrics

This architecture provides a solid foundation for cloud deployment with Azure Container Apps while maintaining simplicity and development velocity.
