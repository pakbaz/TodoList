# TodoList Application Architecture

## Project Overview

**TodoList** is a modern .NET 9 Blazor Server application with full-stack capabilities including:
- Interactive web UI using Blazor Server
- RESTful API endpoints  
- MCP (Model Context Protocol) integration for AI assistant compatibility
- PostgreSQL database with SQLite fallback
- Docker containerization support

## Architecture Type

**Single Service Architecture** - Monolithic application with multiple interfaces (Blazor UI, REST API, MCP Protocol) served from a single ASP.NET Core application.

## Technology Stack

### Frontend
- **Blazor Server**: Interactive server-side rendering with SignalR
- **CSS3**: Custom styling with responsive design
- **HTML5**: Modern markup with accessibility support

### Backend  
- **.NET 9**: Latest LTS framework with C# 13 features
- **ASP.NET Core**: Web application framework
- **Entity Framework Core**: ORM with PostgreSQL and SQLite providers
- **MCP Protocol**: AI assistant integration via JSON-RPC 2.0

### Database
- **Primary**: PostgreSQL 15 (production)
- **Fallback**: SQLite (development/testing)
- **Connection Pooling**: Automatic retry policies and health checks

### Infrastructure
- **Docker**: Multi-stage containerization
- **Docker Compose**: Local development orchestration
- **Health Checks**: Database and application monitoring
- **Application Insights**: Telemetry (production only)

## Project Structure

```
TodoList/
```

## Service Architecture

### Single Container Deployment
- **Application**: TodoList ASP.NET Core app
- **Database**: Separate PostgreSQL service
- **Ports**: 
  - Application: 8080 (HTTP)
  - Database: 5432 (PostgreSQL)

### Application Interfaces
1. **Blazor Server UI** (`/`) - Interactive web interface
2. **REST API** (`/api/todos`) - HTTP endpoints for external integration
3. **MCP Protocol** (`/mcp`) - AI assistant integration
4. **Health Checks** (`/health`) - Application monitoring

## Data Layer

### Database Strategy
- **PostgreSQL**: Primary database for production
- **SQLite**: Automatic fallback for development
- **Entity Framework Core**: Code-first migrations
- **Health Checks**: Database connectivity monitoring

### Entity Model
```csharp
TodoItem {
    Id: int (Primary Key)
    Title: string
    IsDone: bool  
    CreatedAt: DateTime
    UpdatedAt: DateTime
}
```

## Configuration Management

### Connection Strings
- **PostgreSQL**: `Host=localhost;Database=todolistdb;Username=admin;Password=password`
- **SQLite**: `Data Source=todolist.db` (fallback)

### Environment-Specific Settings
- **appsettings.json**: Base configuration
- **appsettings.Development.json**: Development overrides
- **appsettings.Production.json**: Production settings

## Security Considerations

### Current Implementation
- **CORS**: Open policy for MCP client compatibility
- **HTTPS**: Enforced in production (HSTS)
- **User Secrets**: Development credential storage
- **Container Security**: Non-root user execution

### Recommended Enhancements
- **Azure Key Vault**: Secret management
- **Managed Identity**: Azure resource authentication
- **Network Security**: VNet integration for database access
- **Application Gateway**: SSL termination and WAF

## Deployment Target

### Recommended Azure Services
- **Azure Container Apps (ACA)**: Primary deployment target
  - Single container instance
  - External ingress for web access
  - Auto-scaling capabilities
  - Integrated monitoring

### Alternative: Azure Kubernetes Service (AKS)
- For advanced orchestration needs
- Multi-environment deployments
- Complex networking requirements

### Supporting Azure Services
- **Azure Container Registry (ACR)**: Container image storage
- **Azure Database for PostgreSQL**: Managed database service
- **Azure Key Vault**: Secret and certificate management
- **Azure Monitor**: Application insights and logging
- **Azure Application Gateway**: Load balancing and WAF (if needed)

## Scaling Strategy

### Current Limitations
- **Blazor Server**: Session affinity required
- **In-Memory State**: Not suitable for multi-instance deployment
- **SQLite**: Single-user database limitation

### Recommended Improvements
- **Session State**: Redis or SQL Server for shared state
- **Database**: Azure Database for PostgreSQL Flexible Server
- **Caching**: Azure Cache for Redis
- **CDN**: Azure Front Door for static assets

## Migration Path to Microservices

### Future Considerations
If scaling requirements grow, the application can be decomposed into:

1. **TodoList API Service**: Core business logic
2. **Web UI Service**: Blazor frontend
3. **MCP Gateway Service**: AI assistant integration
4. **Notification Service**: Real-time updates
5. **User Management Service**: Authentication and authorization

### Benefits of Current Monolithic Approach
- **Simplicity**: Single deployment unit
- **Performance**: No network latency between components
- **Development Speed**: Faster feature development
- **Debugging**: Easier troubleshooting and testing
