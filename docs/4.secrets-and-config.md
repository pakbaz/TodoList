# Secrets and Configuration Setup

This document outlines the secrets and configuration required for the TodoList application deployment.

## GitHub Repository Secrets

Configure the following secrets in your GitHub repository (`Settings > Secrets and variables > Actions`):

### Azure OIDC Configuration

| Secret Name | Description | Example Value |
|-------------|-------------|---------------|
| `AZURE_CLIENT_ID` | Azure AD App Registration Client ID | `12345678-1234-1234-1234-123456789012` |
| `AZURE_TENANT_ID` | Azure AD Tenant ID | `87654321-4321-4321-4321-210987654321` |
| `AZURE_SUBSCRIPTION_ID` | Azure Subscription ID | `abcdefgh-1234-5678-9012-abcdefghijkl` |

### Optional Secrets

| Secret Name | Description | Required |
|-------------|-------------|----------|
| `DATABASE_ADMIN_PASSWORD` | PostgreSQL admin password (if not auto-generated) | No |

## Azure OIDC Setup Instructions

### 1. Create Azure AD App Registration

```bash
# Create the app registration
az ad app create --display-name "TodoList-GitHub-OIDC" \
  --query appId -o tsv

# Note the Client ID for GitHub secrets
```

### 2. Create Service Principal

```bash
# Replace <CLIENT_ID> with the app ID from step 1
CLIENT_ID="<CLIENT_ID>"

az ad sp create --id $CLIENT_ID

# Get the Object ID of the service principal
OBJECT_ID=$(az ad sp show --id $CLIENT_ID --query id -o tsv)
```

### 3. Configure Federated Credentials

```bash
# For main branch deployments
az ad app federated-credential create \
  --id $CLIENT_ID \
  --parameters '{
    "name": "TodoList-Main-Branch",
    "issuer": "https://token.actions.githubusercontent.com",
    "subject": "repo:<GITHUB_USERNAME>/<REPOSITORY_NAME>:ref:refs/heads/main",
    "description": "GitHub Actions OIDC for main branch",
    "audiences": ["api://AzureADTokenExchange"]
  }'

# For pull request deployments
az ad app federated-credential create \
  --id $CLIENT_ID \
  --parameters '{
    "name": "TodoList-Pull-Requests",
    "issuer": "https://token.actions.githubusercontent.com",
    "subject": "repo:<GITHUB_USERNAME>/<REPOSITORY_NAME>:pull_request",
    "description": "GitHub Actions OIDC for pull requests",
    "audiences": ["api://AzureADTokenExchange"]
  }'

# For workflow dispatch
az ad app federated-credential create \
  --id $CLIENT_ID \
  --parameters '{
    "name": "TodoList-Workflow-Dispatch",
    "issuer": "https://token.actions.githubusercontent.com",
    "subject": "repo:<GITHUB_USERNAME>/<REPOSITORY_NAME>:ref:refs/heads/main",
    "description": "GitHub Actions OIDC for manual workflows",
    "audiences": ["api://AzureADTokenExchange"]
  }'
```

### 4. Assign Azure Permissions

```bash
# Get your subscription ID
SUBSCRIPTION_ID=$(az account show --query id -o tsv)

# Assign Contributor role to the service principal
az role assignment create \
  --assignee $OBJECT_ID \
  --role "Contributor" \
  --scope "/subscriptions/$SUBSCRIPTION_ID"

# Assign additional roles for specific services
az role assignment create \
  --assignee $OBJECT_ID \
  --role "Key Vault Administrator" \
  --scope "/subscriptions/$SUBSCRIPTION_ID"

az role assignment create \
  --assignee $OBJECT_ID \
  --role "AcrPush" \
  --scope "/subscriptions/$SUBSCRIPTION_ID"
```

## Environment Configuration

### Development Environment

- **Purpose**: Feature development and testing
- **Auto-scaling**: Disabled (single instance)
- **High Availability**: Disabled
- **Database**: Basic tier, minimal storage
- **Monitoring**: Standard logging only

### Staging Environment

- **Purpose**: Pre-production testing and validation
- **Auto-scaling**: Limited (1-3 instances)
- **High Availability**: Enabled with zone redundancy
- **Database**: General Purpose tier, moderate storage
- **Monitoring**: Enhanced logging and metrics

### Production Environment

- **Purpose**: Live application serving users
- **Auto-scaling**: Full (2-20 instances)
- **High Availability**: Enabled with geo-redundancy
- **Database**: General Purpose/Memory Optimized tier, full backup
- **Monitoring**: Complete observability stack

|-------------|-------------|--------|

| `application-insights-connection-string` | Application Insights connection | Auto-generated from Terraform |

## Security Configuration

### Network Security

- All services deployed in private subnets
- Private endpoints for Key Vault, ACR, and PostgreSQL
- Network Security Groups with minimal required access
- Azure Application Gateway for ingress with WAF

### Identity and Access

- Managed Identity for all Azure service authentication
- Key Vault for all secrets management
- RBAC with principle of least privilege
- Azure AD integration for PostgreSQL authentication

### Data Protection

- TLS 1.2+ for all communications
- Encryption at rest for all storage
- Backup encryption for PostgreSQL
- Secrets never stored in plaintext

## Troubleshooting

### Common Issues

1. **OIDC Authentication Failures**
   - Verify federated credentials configuration
   - Check GitHub repository secrets
   - Ensure correct audience in federated credential

2. **Terraform State Lock**
   - Wait for concurrent operations to complete
   - Manually break lock if necessary: `terraform force-unlock LOCK_ID`

3. **Container App Deployment Issues**
   - Check container registry authentication
   - Verify image exists and is accessible
   - Review Container App logs in Azure Portal

4. **Database Connection Issues**
   - Verify private DNS zone configuration
   - Check NSG rules for database subnet
   - Validate connection string in Key Vault
