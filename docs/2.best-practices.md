# Azure Infrastructure as Code and CI/CD Best Practices

## Azure Container Apps Best Practices

### Security Configuration
- **Use managed identities** for secure, credential-free access to Azure resources like Key Vault, Container Registry, and databases
- **Deploy in private networks** with VNet integration to isolate from public internet
- **Implement network security groups (NSGs)** to control traffic flow with granular rules
- **Enable Azure Key Vault integration** for secure storage of secrets, connection strings, and certificates
- **Configure HTTPS enforcement** to protect data in transit (set allowInsecure: false)
- **Use mutual TLS (mTLS)** for service-to-service communication authentication
- **Implement Azure Application Gateway with WAF** for public-facing applications to protect against OWASP attacks
- **Control outbound traffic** with user-defined routes to Azure Firewall or NAT Gateway

### Application Configuration
- **Use environment variables** instead of appsettings.json for configuration to enable environment-specific deployments
- **Store sensitive values in Azure Key Vault** and reference them as environment variables
- **Configure health probes** (liveness, readiness, startup) appropriate to application behavior
- **Implement proper resource allocation** (CPU/memory) based on application requirements
- **Enable Application Insights** for telemetry, monitoring, and performance tracking

### Container and Registry Best Practices
- **Use Azure Container Registry (ACR)** with Premium SKU for production workloads
- **Authenticate to ACR using managed identity** instead of admin credentials
- **Implement geo-replication** for high availability across regions
- **Use immutable image tags** (avoid 'latest' tag) with SHA-based versioning
- **Scan container images** for vulnerabilities using Microsoft Defender for Containers
- **Use minimal base images** (Alpine, Chiselled Ubuntu) to reduce attack surface

### Scaling and Performance
- **Configure autoscaling rules** based on HTTP requests, Azure Queue, or custom metrics
- **Use appropriate revision modes** (Single for stateless apps, Multiple for gradual rollouts)
- **Implement sticky sessions** if application requires session affinity
- **Monitor JVM metrics** for Java applications (memory, GC, threads)

## Azure PostgreSQL Flexible Server Best Practices

### Security Configuration
- **Deploy in VNet** with private access for network isolation
- **Use Azure Active Directory authentication** instead of database passwords
- **Implement row-level security** for fine-grained data access control
- **Enable connection throttling** to protect against brute force attacks
- **Configure firewall rules** to restrict database access to known IP ranges
- **Use customer-managed keys (CMK)** for data encryption at rest when required for compliance
- **Disable public network access** when possible

### High Availability and Backup
- **Configure high availability (HA)** with zone redundancy for production workloads
- **Set backup retention** between 7-35 days based on business requirements
- **Implement read replicas** for read scaling and disaster recovery
- **Use point-in-time restore** capabilities for data recovery scenarios

### Performance and Monitoring
- **Monitor database metrics** including CPU, memory, IOPS, and connection counts
- **Configure appropriate compute tier** (Burstable, General Purpose, Memory Optimized)
- **Implement connection pooling** to optimize database connections
- **Regular security audits** to identify and remediate vulnerabilities

## Azure Bicep Infrastructure as Code Best Practices

### Template Structure and Organization
- **Use modular approach** with Bicep modules for reusable components
- **Implement parameter files** for environment-specific configurations
- **Use descriptive resource naming** with consistent naming conventions
- **Add comments and descriptions** using @description() decorators for self-documenting code
- **Organize resources logically** within modules (e.g., networking, compute, storage)

### Security and Compliance
- **Use Azure Policy** for governance and compliance enforcement
- **Implement least privilege access** with RBAC role assignments
- **Store templates in version control** with proper branching strategies
- **Use Microsoft Defender for Cloud** to scan for IaC misconfigurations
- **Implement deployment validation** with pre-deployment checks

### Deployment Patterns
- **Use deployment stacks** for lifecycle management of related resources
- **Implement idempotent deployments** that can run multiple times safely
- **Use conditional deployment** with environment-specific parameters
- **Implement resource tagging** for cost management and governance
- **Use output values** to pass information between modules

### Parameterization and Configuration
- **Use allowed values** for parameters where appropriate to prevent errors
- **Implement default values** for optional parameters
- **Use secure parameters** for sensitive values like passwords
- **Validate input parameters** with decorators (@minLength, @maxLength, etc.)
- **Use variables** for complex expressions and computed values

## GitHub Actions CI/CD Best Practices

### Security and Authentication
- **Use OIDC authentication** instead of service principal secrets for Azure
- **Implement least privilege permissions** for workflow tokens
- **Store secrets in GitHub Secrets** and reference them securely
- **Pin action versions** to specific commits for security
- **Use environment protection rules** for production deployments

### Workflow Design
- **Separate build and deploy stages** with clear dependencies
- **Use artifacts** to pass build outputs between jobs
- **Implement parallel execution** where possible to reduce pipeline time
- **Use matrix builds** for testing across multiple environments
- **Implement approval gates** for production deployments

### Error Handling and Monitoring
- **Implement retry logic** for transient failures
- **Use status checks** to ensure deployment health
- **Configure notifications** for pipeline failures
- **Implement rollback strategies** for failed deployments
- **Monitor deployment metrics** and application health post-deployment

## Azure Key Vault Best Practices

### Access and Security
- **Use managed identities** for application access to Key Vault
- **Implement RBAC** with Key Vault-specific roles (Key Vault Secrets User, etc.)
- **Enable soft delete and purge protection** for production environments
- **Use private endpoints** for secure network access
- **Implement access policies** with principle of least privilege

### Secret Management
- **Use versioned secrets** for rotation scenarios
- **Implement automatic rotation** for database passwords and API keys
- **Use separate Key Vaults** for different environments (dev, staging, prod)
- **Monitor access logs** for audit and security purposes
- **Use Key Vault references** in Azure services instead of direct secret storage

## Monitoring and Observability Best Practices

### Logging Strategy
- **Use Azure Log Analytics** for centralized log collection
- **Configure structured logging** with consistent log formats
- **Implement log retention policies** based on compliance requirements
- **Send application logs to stdout/stderr** for container log collection
- **Use correlation IDs** for distributed tracing

### Metrics and Alerting
- **Configure Azure Monitor alerts** for critical metrics
- **Implement health check endpoints** for application monitoring
- **Monitor resource utilization** (CPU, memory, storage, network)
- **Set up budget alerts** for cost management
- **Use Application Map** for dependency visualization

### Performance Monitoring
- **Configure Application Insights** for application performance monitoring
- **Implement custom metrics** for business-specific monitoring
- **Use distributed tracing** for microservices architectures
- **Monitor database performance** with query insights
- **Set up synthetic monitoring** for external availability checks

## Cost Optimization Best Practices

### Resource Management
- **Right-size resources** based on actual usage patterns
- **Use Azure Spot instances** for non-critical workloads
- **Implement auto-shutdown** for development environments
- **Use reserved instances** for predictable workloads
- **Monitor cost trends** with Azure Cost Management

### Container Apps Optimization
- **Configure appropriate scaling rules** to avoid over-provisioning
- **Use consumption-based pricing** with proper min/max replica settings
- **Optimize container images** to reduce startup time and resource usage
- **Implement resource quotas** to control costs
- **Use development/test pricing** for non-production environments
