# Azure Infrastructure as Code and CI/CD Best Practices

## Azure Container Apps Best Practices

### Security
- **Use managed identities** to access Azure AD protected resources without storing credentials
- **Enable HTTPS enforcement** and disable insecure HTTP traffic using `ingressAllowInsecure: false`
- **Use Azure Key Vault** for storing sensitive configuration values and secrets
- **Deploy in private networks** with VNet integration to isolate from public internet
- **Implement mutual TLS (mTLS)** for service-to-service authentication
- **Use least-privilege RBAC** roles for accessing Azure resources
- **Enable system-assigned or user-assigned managed identities** for secure authentication

### Configuration
- **Use external ingress carefully** - set `ingressExternal: false` for internal-only access
- **Configure health checks** with proper liveness and readiness probes
- **Set appropriate resource limits** for CPU and memory allocation
- **Enable zone redundancy** for high availability deployments
- **Use workload profiles** for better resource management and isolation

### Secrets Management
- **Reference Key Vault secrets** using managed identities instead of inline values
- **Use Key Vault URLs** for secret references: `https://vault.vault.azure.net/secrets/secret-name`
- **Configure proper identity for Key Vault access** - either system-assigned or user-assigned
- **Avoid hardcoding secrets** in environment variables or configuration files

## Azure Container Registry Best Practices

### Security
- **Disable admin user** by setting `acrAdminUserEnabled: false`
- **Use Premium SKU** for production workloads to enable advanced security features
- **Enable Azure AD authentication** with `azureADAuthenticationAsArmPolicyStatus: enabled`
- **Implement private endpoints** for network isolation
- **Use customer-managed keys** for encryption at rest
- **Enable content trust** with `trustPolicyStatus: enabled`
- **Configure quarantine policies** to scan images before deployment

### Image Management
- **Use immutable image tags** based on git commit SHA for traceability
- **Implement image scanning** and quarantine policies
- **Configure soft delete policies** for accidental deletion protection
- **Use geo-replication** for global availability and disaster recovery

## Azure Key Vault Best Practices

### Access Control
- **Use managed identities** for application access to Key Vault
- **Implement least-privilege access** with role-based access control (RBAC)
- **Enable Key Vault access policies** for specific Azure services
- **Use separate Key Vaults** for different environments (dev, staging, prod)
- **Enable auditing and monitoring** for all Key Vault operations

### Secret Management
- **Use Key Vault references** in Container Apps instead of direct secret values
- **Enable auto-rotation** for secrets where possible
- **Implement secret versioning** for better change management
- **Use customer-managed keys** for additional encryption layer

## GitHub Actions CI/CD Best Practices

### Authentication
- **Use OpenID Connect (OIDC)** for secure Azure authentication
- **Avoid storing service principal secrets** in repository secrets
- **Use federated identity credentials** for GitHub to Azure authentication
- **Implement least-privilege permissions** for deployment roles

### Workflow Design
- **Use separate jobs** for build and deployment stages
- **Implement artifact passing** between jobs using GitHub Actions artifacts
- **Pin action versions** to specific commits or tags for security
- **Use environment protection rules** for production deployments
- **Implement approval gates** for critical environment deployments

### Security
- **Never echo secrets** in workflow logs
- **Use environment-specific secrets** and variables
- **Implement branch protection rules** for main branch
- **Scan for vulnerabilities** in dependencies and container images
- **Use signed commits** and verified publishers for actions

## Azure Developer CLI (azd) Best Practices

### Template Structure
- **Follow azd conventions** with `infra/`, `src/`, and `azure.yaml` structure
- **Use Bicep for infrastructure** as the preferred IaC language
- **Implement parameterization** for environment-specific configurations
- **Include health checks** and monitoring in templates
- **Use Azure Verified Modules (AVM)** for standardized resource definitions

### Environment Management
- **Use separate azd environments** for development, staging, and production
- **Configure environment-specific parameters** in `.azure/` folder
- **Implement proper naming conventions** for resources
- **Use resource tagging** for governance and cost management

### CI/CD Integration
- **Use `azd pipeline config`** for automated CI/CD setup
- **Configure OIDC authentication** for secure GitHub Actions integration
- **Implement infrastructure validation** in pipelines
- **Use `azd deploy` for application deployments**
