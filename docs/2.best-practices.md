# Azure Infrastructure as Code & CI/CD Best Practices

This document provides comprehensive best practices for implementing Infrastructure as Code (IaC) and CI/CD pipelines for ASP.NET Core applications deployed to Azure Container Apps, based on current Azure, Terraform, and DevOps guidance.

## Azure Container Apps Best Practices

### Container App Environment Configuration
- **Use Managed Environments**: Deploy Container Apps within managed environments for better resource isolation and networking control
- **Zone Redundancy**: Enable zone redundancy for high availability in production environments using `ZoneRedundant` mode
- **VNet Integration**: Use infrastructure subnet integration for enhanced network security and private connectivity
- **Log Analytics Integration**: Always configure Log Analytics workspace for centralized logging and monitoring

### Container Configuration
- **Resource Sizing**: Start with minimal resources (0.25 CPU, 0.5Gi memory) and scale based on load testing results
- **Health Probes**: Implement liveness, readiness, and startup probes for robust health monitoring
- **Single Responsibility**: Deploy one service per container app for better scaling and maintenance
- **Immutable Images**: Use immutable container images tagged with commit SHA for reliable deployments

### Networking and Security
- **Private Endpoints**: Use private endpoints for database and Key Vault connectivity
- **Ingress Configuration**: 
  - Disable insecure connections in production (`allow_insecure_connections = false`)
  - Use external ingress only when necessary; prefer internal with Application Gateway for public access
  - Configure appropriate client certificate modes
- **Managed Identity**: Always enable system-assigned managed identity for secure service-to-service authentication

### Scaling and Performance
- **Revision Mode**: Use "Single" revision mode for stateless applications
- **Auto-scaling**: Configure HTTP scale rules based on concurrent requests
- **Traffic Distribution**: Use traffic weights for blue-green deployments and gradual rollouts

## PostgreSQL Best Practices

### Server Configuration
- **Flexible Server**: Use Azure Database for PostgreSQL Flexible Server for better performance and flexibility
- **Version Selection**: Use PostgreSQL 16 for latest features and security updates
- **SKU Selection**: Start with `GP_Standard_D2s_v3` for general purpose workloads
- **High Availability**: Enable `ZoneRedundant` high availability for production environments
- **Storage**: Configure appropriate storage tier and enable auto-growth

### Security Configuration
- **Authentication**: 
  - Enable Microsoft Entra ID authentication for administrative access
  - Use strong passwords for built-in accounts with automatic rotation
  - Prefer Azure AD authentication over password authentication where possible
- **Network Security**:
  - Use private endpoints for secure connectivity from Container Apps
  - Disable public access when using private endpoints
  - Configure firewall rules restrictively
- **Encryption**: Enable customer-managed keys for data encryption when required for compliance

### Database Management
- **Database Creation**: Create application databases with appropriate charset (UTF8) and collation (en_US.utf8)
- **Connection Pooling**: Configure connection pooling in application for optimal performance
- **Backup Strategy**: Configure automated backups with appropriate retention periods
- **Monitoring**: Enable diagnostic settings to send logs to Log Analytics

## Azure Key Vault Best Practices

### Access Control and Security
- **RBAC over Access Policies**: Use Azure RBAC instead of legacy access policies for better security and PIM support
- **Managed Identity Access**: Use managed identities for all application access to Key Vault
- **Least Privilege**: Apply principle of least privilege with granular RBAC roles
- **Just-in-Time Access**: Use Privileged Identity Management (PIM) for administrative access
- **Network Security**: Use private endpoints and restrict network access

### Secret Management
- **Secret Rotation**: Implement automated secret rotation where possible
- **Separation of Concerns**: Use separate Key Vaults per environment (dev, staging, production)
- **Secret Naming**: Use consistent naming conventions for secrets (e.g., `{service}-{environment}-{purpose}`)
- **Audit Trail**: Enable logging and monitoring for all Key Vault access

### Integration Patterns
- **CSI Secrets Store**: Use Azure Key Vault Provider for Secrets Store CSI driver in Kubernetes/Container Apps
- **Application Configuration**: Read secrets as files or environment variables using managed identity
- **Connection Strings**: Store database connection strings and API keys in Key Vault

## Terraform Infrastructure as Code Best Practices

### Module Organization
- **Modular Design**: Create reusable modules for common infrastructure patterns
- **Variable Validation**: Use variable validation rules to ensure proper input values
- **Resource Naming**: Use Azure naming conventions with consistent prefixes and suffixes
- **Output Values**: Provide meaningful outputs for resource IDs and connection strings

### Security and State Management
- **Remote State**: Use Azure Storage backend for Terraform state with encryption
- **State Locking**: Enable state locking using Azure Storage Blob lease
- **Sensitive Variables**: Mark sensitive variables as `sensitive = true`
- **No Hardcoded Secrets**: Never hardcode secrets in Terraform files

### Resource Configuration
- **Resource Dependencies**: Use explicit depends_on when implicit dependencies are not sufficient
- **Lifecycle Rules**: Use lifecycle rules to prevent accidental resource deletion
- **Resource Tagging**: Apply consistent tagging strategy for cost management and governance
- **Provider Versions**: Pin provider versions for consistency and stability

## GitHub Actions CI/CD Best Practices

### Workflow Security
- **OIDC Authentication**: Use OpenID Connect for secure, keyless authentication to Azure
- **Least Privilege Tokens**: Use minimal GITHUB_TOKEN permissions required for each job
- **Environment Protection**: Use GitHub Environments with required reviewers for production deployments
- **Secret Management**: Store sensitive values in GitHub Secrets, never in code

### Pipeline Architecture
- **Build and Deploy Separation**: Separate build and deployment jobs for better control and reusability
- **Artifact Management**: Use artifacts to pass build outputs between jobs
- **Matrix Builds**: Use matrix strategies for testing across multiple environments
- **Parallel Execution**: Run independent jobs in parallel to reduce total pipeline time

### Container Image Management
- **Image Tagging**: Tag images with git commit SHA for traceability
- **Registry Security**: Use Azure Container Registry with managed identity authentication
- **Image Scanning**: Implement security scanning for container images
- **Multi-stage Builds**: Use multi-stage Docker builds to minimize image size

### Deployment Strategies
- **Idempotent Deployments**: Ensure all deployments are idempotent and can be safely re-run
- **Health Checks**: Implement proper health checks and wait for successful deployment validation
- **Rollback Strategy**: Have automated rollback capabilities for failed deployments
- **Database Migrations**: Handle database schema changes carefully with backward compatibility

## Monitoring and Observability Best Practices

### Application Insights Integration
- **Telemetry Collection**: Enable Application Insights for all application components
- **Custom Metrics**: Implement custom metrics for business-specific monitoring
- **Dependency Tracking**: Monitor external dependencies including databases and APIs
- **Performance Monitoring**: Track response times, error rates, and resource utilization

### Log Management
- **Structured Logging**: Use structured logging with correlation IDs for request tracing
- **Log Levels**: Implement appropriate log levels (Debug, Info, Warning, Error)
- **Centralized Logging**: Send all logs to Azure Log Analytics workspace
- **Log Retention**: Configure appropriate log retention policies for cost optimization

### Alerting and Monitoring
- **Health Endpoints**: Implement `/health` and `/health/ready` endpoints for monitoring
- **Alert Rules**: Create alert rules for critical metrics and error conditions
- **Dashboard Creation**: Build monitoring dashboards for operational visibility
- **SLA Monitoring**: Monitor and alert on service level objectives

## Security Best Practices

### Identity and Access Management
- **Managed Identities**: Use system-assigned managed identities wherever possible
- **Service Principals**: Avoid service principals unless managed identities are not supported
- **Certificate Authentication**: Use certificate credentials over client secrets when service principals are required
- **Regular Rotation**: Implement regular credential rotation policies

### Network Security
- **Private Connectivity**: Use private endpoints for all Azure PaaS services
- **Network Segmentation**: Implement proper network segmentation with VNets and subnets
- **Firewall Rules**: Configure restrictive firewall rules and NSG policies
- **Application Gateway**: Use Application Gateway with WAF for public-facing applications

### Data Protection
- **Encryption at Rest**: Enable encryption at rest for all data stores
- **Encryption in Transit**: Use TLS/HTTPS for all communications
- **Key Management**: Use customer-managed keys when required for compliance
- **Data Classification**: Classify and protect data according to sensitivity levels

## Cost Optimization Best Practices

### Resource Sizing
- **Right-sizing**: Start small and scale based on actual usage patterns
- **Auto-scaling**: Use auto-scaling to optimize costs during low-traffic periods
- **Reserved Instances**: Use reserved instances for predictable workloads
- **Spot Instances**: Consider spot instances for non-critical workloads

### Resource Management
- **Lifecycle Management**: Implement resource lifecycle management for temporary environments
- **Resource Tagging**: Use tags for cost allocation and chargeback
- **Monitoring**: Monitor costs regularly and set up budget alerts
- **Cleanup Automation**: Automate cleanup of unused resources and old deployments

This comprehensive set of best practices ensures secure, scalable, and maintainable infrastructure deployments for modern cloud-native applications on Azure.
