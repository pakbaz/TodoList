# TodoList Application - Infrastructure as Code and CI/CD Implementation Plan

## Executive Summary

This implementation plan details the deployment strategy for the TodoList .NET 9 Blazor application to Azure Container Apps using Infrastructure as Code (Bicep) and GitHub Actions CI/CD. The plan follows Azure best practices for security, scalability, and operational excellence.

## Target Azure Architecture

### Core Infrastructure Components

1. **Resource Group** - Container for all related resources
2. **Azure Container Apps Environment** - Managed serverless container platform
3. **Azure Container Registry (ACR)** - Premium SKU for container image storage
4. **Azure PostgreSQL Flexible Server** - Primary database with high availability
5. **Azure Key Vault** - Secure storage for secrets and connection strings
6. **Azure Log Analytics Workspace** - Centralized logging and monitoring
7. **Application Insights** - Application performance monitoring

### Network Architecture

1. **Virtual Network (VNet)** - Private network for secure communication
2. **Private Subnets** - Separate subnets for Container Apps and PostgreSQL
3. **Network Security Groups (NSGs)** - Traffic control and security rules
4. **Private DNS Zones** - Internal name resolution
5. **Azure Application Gateway** (Optional) - WAF-enabled ingress for public access

### Security Components

1. **Managed Identity** - System-assigned identity for the Container App
2. **Key Vault Access Policies** - Least privilege access to secrets
3. **Private Endpoints** - Secure communication to Azure services
4. **TLS/SSL Certificates** - HTTPS enforcement
5. **Azure Monitor** - Security monitoring and alerting

## Bicep Template Architecture

### Modular Structure

```
/infra/
├── main.bicep                 # Main orchestration template
├── parameters/
│   ├── dev.bicepparam        # Development environment parameters
│   ├── staging.bicepparam    # Staging environment parameters
│   └── prod.bicepparam       # Production environment parameters
└── modules/
    ├── network.bicep         # VNet, subnets, NSGs
    ├── keyvault.bicep        # Key Vault configuration
    ├── postgresql.bicep      # Database configuration
    ├── container-registry.bicep # ACR configuration
    ├── container-apps.bicep  # Container Apps environment and app
    ├── monitoring.bicep      # Log Analytics and App Insights
    └── security.bicep        # Security configurations
```

## CI/CD Pipeline Strategy

### GitHub Actions Workflow Structure

```
/.github/workflows/
├── deploy.yml               # Main deployment workflow
├── validate.yml            # Infrastructure validation
└── cleanup.yml             # Resource cleanup (dev environments)
```

### Workflow Stages

#### Stage 1: Infrastructure Setup
**Triggers**: Push to main branch, manual dispatch
**Steps**:
1. OIDC authentication to Azure
2. Validate Bicep templates
3. Deploy infrastructure using deployment stacks
4. Verify resource provisioning
5. Update Key Vault with database secrets

#### Stage 2: Application Build
**Dependencies**: None (runs in parallel with Stage 1)
**Steps**:
1. Checkout source code
2. Setup .NET 9 SDK
3. Restore NuGet packages
4. Run unit tests
5. Build application
6. Build Docker image
7. Push image to ACR

#### Stage 3: Database Setup
**Dependencies**: Stage 1 complete, PostgreSQL deployed
**Steps**:
1. Run database migration scripts
2. Seed initial data (if required)
3. Verify database connectivity
4. Update connection string in Key Vault

#### Stage 4: Application Deployment
**Dependencies**: Stages 1, 2, 3 complete
**Steps**:
1. Deploy Container App with new image
2. Configure environment variables from Key Vault
3. Validate health check endpoints
4. Run smoke tests
5. Configure traffic routing

#### Stage 5: Post-Deployment Verification
**Dependencies**: Stage 4 complete
**Steps**:
1. Verify application accessibility
2. Check database connectivity
3. Validate monitoring and alerting
4. Run integration tests
5. Update deployment status

## Secret Management Strategy

### Azure Key Vault Configuration

**Secret Categories**:
1. **Database Secrets**
   - PostgreSQL connection string
   - Database administrator password
   - Application user credentials

2. **Application Secrets**
   - Application Insights instrumentation key
   - Third-party API keys
   - Encryption keys

3. **Infrastructure Secrets**
   - Container registry credentials
   - Certificate information
   - Service principal credentials (if needed)

### Access Control Strategy

**Managed Identity Access**:
- Container App uses system-assigned managed identity
- Key Vault access policy grants "Get" and "List" permissions
- Secrets accessed via Key Vault references in Container App

**CI/CD Access**:
- GitHub Actions uses OIDC with federated credentials
- Least privilege access to Key Vault for secret management
- Separate service principal for infrastructure deployment

### Secret Rotation Strategy

**Automated Rotation**:
- Database passwords rotated every 90 days
- Application Insights keys rotated annually
- Certificate renewal automation

**Manual Rotation**:
- API keys rotated based on provider requirements
- Infrastructure secrets rotated on security events
