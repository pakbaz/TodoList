# Infrastructure as Code and CI/CD Implementation Plan

Based on the TodoList application architecture and Azure best practices, this document outlines the comprehensive implementation plan for Infrastructure as Code (IaC) using Terraform and CI/CD pipeline using GitHub Actions.

## Target Azure Resources

### Core Infrastructure Components

1. **Resource Group**
   - Single resource group to contain all resources
   - Naming: `rg-todolist-{environment}`
   - Location: East US 2 (primary), West US 2 (secondary for geo-redundancy)

2. **Virtual Network & Networking**
   - VNet with dedicated subnets for Container Apps and private endpoints
   - Address space: `10.0.0.0/16`
   - Container Apps subnet: `10.0.1.0/24`
   - Private endpoints subnet: `10.0.2.0/24`
   - Network Security Groups with restrictive rules

3. **Azure Container Registry (ACR)**
   - Premium SKU for geo-replication and advanced security features
   - Private endpoint connectivity
   - Admin user disabled (use managed identity)
   - Geo-replication for high availability

4. **Azure Container Apps Environment**
   - Integrated with VNet for enhanced security
   - Log Analytics workspace integration
   - Zone redundancy enabled for high availability

5. **Azure Database for PostgreSQL Flexible Server**
   - PostgreSQL version 16
   - SKU: `GP_Standard_D2s_v3` (General Purpose, 2 vCores)
   - High availability with zone redundancy
   - Private endpoint connectivity
   - Automatic backups with 7-day retention

6. **Azure Key Vault**
   - RBAC-based access control (no legacy access policies)
   - Private endpoint connectivity
   - Soft delete and purge protection enabled
   - Customer-managed keys support

7. **Azure Monitor & Observability**
   - Log Analytics workspace for centralized logging
   - Application Insights for application telemetry
   - Azure Monitor alerts for critical metrics

## CI/CD Pipeline Implementation

### GitHub Actions Workflow Structure

```yaml
# .github/workflows/deploy.yml
name: Build and Deploy TodoList Application

on:
  push:
    branches: [ main ]
  pull_request:
    branches: [ main ]
  workflow_dispatch:
    inputs:
      environment:
        description: 'Environment to deploy to'
        required: true
        default: 'dev'
        type: choice
        options:
        - dev
        - staging
        - prod

env:
  AZURE_CLIENT_ID: ${{ vars.AZURE_CLIENT_ID }}
  AZURE_TENANT_ID: ${{ vars.AZURE_TENANT_ID }}
  AZURE_SUBSCRIPTION_ID: ${{ vars.AZURE_SUBSCRIPTION_ID }}
```

### CI/CD Jobs Structure

1. **Build Job**
   - Checkout source code
   - Setup .NET 9 SDK
   - Restore NuGet packages
   - Build application
   - Run unit tests
   - Build Docker image
   - Push image to ACR with git commit SHA tag
   - Upload build artifacts

2. **Infrastructure Job** (depends on build)
   - Checkout source code
   - Setup Terraform
   - Login to Azure via OIDC
   - Terraform init with remote state
   - Terraform plan with output to file
   - Terraform apply (auto-approve for dev, manual approval for prod)
   - Output infrastructure details

3. **Deploy Job** (depends on infrastructure)
   - Download build artifacts
   - Login to Azure via OIDC
   - Deploy container app with new image
   - Run database migrations if needed
   - Verify deployment health
   - Run smoke tests

## Secret Management Strategy

### Azure Key Vault Integration

1. **Database Connection Strings**
   - Store PostgreSQL connection string in Key Vault
   - Use managed identity to access Key Vault from Container Apps
   - Secret name: `{app-name}-{environment}-db-connection-string`

2. **Application Secrets**
   - API keys and external service credentials stored in Key Vault
   - Application reads secrets via CSI Secrets Store driver
   - Automatic secret rotation where supported

3. **GitHub Secrets Configuration**
   - `AZURE_CLIENT_ID`: Workload identity client ID
   - `AZURE_TENANT_ID`: Azure tenant ID
   - `AZURE_SUBSCRIPTION_ID`: Target subscription ID
   - Environment-specific variables for different deployment targets

### Secret Rotation Strategy

1. **Automated Rotation**
   - Database passwords rotated every 90 days using Key Vault rotation
   - Application restart triggered automatically after rotation
   - Monitoring alerts for rotation failures

2. **Manual Rotation**
   - API keys and external service credentials rotated manually
   - Documented procedures for emergency rotation
   - Zero-downtime rotation using blue-green deployment

## Infrastructure Deployment Strategy

### Idempotent Deployment Approach

1. **Resource Detection**
   - Use Terraform data sources to detect existing resources
   - Conditional resource creation based on existence
   - No destructive operations on existing resources

2. **State Management**
   - Remote state stored in Azure Storage with encryption
   - State locking using Azure Storage blob lease
   - Backup strategy for state files

3. **Rollback Capabilities**
   - Git tag creation for successful deployments
   - Terraform state backup before each deployment
   - Automated rollback to previous working configuration

### Database Migration Strategy

1. **Schema Migrations**
   - Entity Framework migrations applied during deployment
   - Backward-compatible changes only
   - Database backup before migrations in production

2. **Data Migrations**
   - Separate data migration scripts for complex changes
   - Gradual migration approach for large datasets
   - Rollback scripts prepared for each migration

## Risk Mitigation

### Infrastructure Risks
- **Resource Conflicts**: Use unique naming with random suffixes
- **Service Limits**: Monitor Azure quotas and request increases
- **Regional Outages**: Implement multi-region deployment capability

### Deployment Risks
- **Failed Deployments**: Implement automatic rollback mechanisms
- **Database Corruption**: Maintain regular backups and test restoration
- **Security Breaches**: Implement defense-in-depth security measures

### Operational Risks
- **Secret Exposure**: Use short-lived tokens and regular rotation
- **Performance Degradation**: Implement comprehensive monitoring
- **Cost Overruns**: Set up budget alerts and cost optimization

This implementation plan provides a comprehensive roadmap for deploying the TodoList application with enterprise-grade infrastructure and CI/CD capabilities while maintaining security, scalability, and operational excellence.
