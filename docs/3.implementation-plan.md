# Infrastructure as Code and CI/CD Implementation Plan

## Project Overview

This implementation plan details the setup of Infrastructure as Code (IaC) and CI/CD pipeline for the TodoList ASP.NET Core Blazor application. The solution will use Azure Container Apps as the primary deployment target with supporting Azure services.

## Target Azure Architecture

### Core Azure Services

1. **Azure Container Apps (ACA)**
   - Primary hosting platform for the TodoList application
   - External ingress for web access
   - Integrated with Azure Monitor for logging and metrics
   - Auto-scaling based on HTTP requests

2. **Azure Container Registry (ACR)**
   - Private container image storage
   - Integration with GitHub Actions for automated image builds
   - Managed identity access for secure image pulls

3. **Azure Database for PostgreSQL Flexible Server**
   - Managed PostgreSQL service for production data storage
   - Private endpoint connectivity for security
   - Automated backups and high availability

4. **Azure Key Vault**
   - Centralized secret management
   - Database connection strings and sensitive configuration
   - Managed identity access from Container Apps

5. **Azure Monitor & Application Insights**
   - Application performance monitoring
   - Structured logging and metrics collection
   - Real-time application health monitoring

6. **Azure Virtual Network**
   - Network isolation and security
   - Private endpoints for PostgreSQL and Key Vault
   - Network security groups for traffic control

## Implementation Strategy

### Phase 1: Azure Developer CLI Setup

#### 1.1 Initialize azd Project
```bash
azd init
```
- Configure azure.yaml with service definitions
- Set up environment configurations
- Define resource naming conventions

#### 1.2 Generate Infrastructure Templates
```bash
azd infra generate
```
- Create Bicep templates in `infra/` directory
- Use Azure Verified Modules (AVM) where possible
- Implement modular infrastructure design

#### 1.3 Environment Configuration
- Development environment: Basic resources, cost-optimized
- Production environment: High availability, security-focused
- Use environment-specific parameter files

### Phase 2: Infrastructure as Code Development

#### 2.1 Core Infrastructure (main.bicep)
- Resource Group creation
- Virtual Network with subnets
- Network Security Groups
- Azure Container Registry
- Azure Key Vault
- Log Analytics Workspace

#### 2.2 Database Infrastructure (database.bicep)
- PostgreSQL Flexible Server
- Private endpoint configuration
- Database creation and user setup
- Connection string generation and Key Vault storage

#### 2.3 Container Apps Infrastructure (containerApps.bicep)
- Container Apps Environment
- Container App definition
- Managed identity configuration
- Environment variables and secrets configuration
- Ingress and scaling rules

#### 2.4 Security Configuration (security.bicep)
- Managed identity creation
- Role assignments for Key Vault access
- Role assignments for ACR image pull
- Network security configurations

### Phase 3: CI/CD Pipeline Implementation

#### 3.1 GitHub Actions Workflow Structure
```yaml
name: Deploy to Azure Container Apps

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  build:
    # Build and test application
    # Build and push Docker image
    # Upload deployment artifacts
    
  deploy:
    # Deploy infrastructure using azd
    # Deploy application to Container Apps
    # Run post-deployment verification
```

#### 3.2 Build Job Implementation
- .NET application build and test
- Docker image creation with multi-stage build
- Security scanning of container images
- Push to Azure Container Registry with SHA-based tags
- Generate deployment artifacts

#### 3.3 Deploy Job Implementation
- Infrastructure deployment using `azd deploy`
- Application deployment to Container Apps
- Database migration execution
- Health check verification
- Deployment status reporting

### Phase 4: Security Implementation

#### 4.1 Authentication and Authorization
- OpenID Connect (OIDC) federated identity for GitHub Actions
- User-assigned managed identity for Container Apps
- System-assigned managed identity for ACR access
- Role-based access control (RBAC) assignments

#### 4.2 Secret Management
- Database connection strings in Key Vault
- Application secrets in Key Vault
- Container Apps Key Vault references
- Secret rotation policies

#### 4.3 Network Security
- Private endpoints for PostgreSQL and Key Vault
- Container Apps in dedicated subnet
- Network security group rules
- Application Gateway for SSL termination (optional)

## Environment Strategy

### Development Environment
- **Resource Naming**: `todolist-dev-{resource-type}-{unique-suffix}`
- **Cost Optimization**: Basic SKUs, minimal replicas
- **Database**: Basic tier PostgreSQL
- **Container Apps**: Consumption plan
- **Monitoring**: Basic Application Insights

### Production Environment
- **Resource Naming**: `todolist-prod-{resource-type}-{unique-suffix}`
- **High Availability**: Zone redundancy where available
- **Database**: General Purpose tier with backup retention
- **Container Apps**: Dedicated plan with auto-scaling
- **Monitoring**: Advanced Application Insights with alerting

## Secret Management Strategy

### Key Vault Implementation
- **Separation by Environment**: Separate Key Vault per environment
- **Access Control**: Managed identities only, no access keys
- **Secret Types**:
  - `postgresql-connection-string`: Database connection
  - `application-insights-key`: Monitoring configuration
  - `jwt-signing-key`: Application authentication (if needed)

### Container Apps Secret Configuration
```yaml
secrets:
  - name: "postgresql-connection"
    keyVaultUrl: "https://{keyvault-name}.vault.azure.net/secrets/postgresql-connection-string"
    identity: "{user-assigned-identity-resource-id}"
```

## CI/CD Pipeline Configuration

### GitHub Actions Variables and Secrets
- **Repository Variables**:
  - `AZURE_CLIENT_ID`: Federated identity client ID
  - `AZURE_TENANT_ID`: Azure AD tenant ID
  - `AZURE_SUBSCRIPTION_ID`: Target subscription

- **Environment Variables** (per environment):
  - `RESOURCE_GROUP_NAME`: Target resource group
  - `CONTAINER_REGISTRY_NAME`: ACR instance name
  - `ENVIRONMENT_NAME`: azd environment name

### Workflow Triggers
- **Push to main**: Deploy to production
- **Pull Request**: Deploy to development environment for testing
- **Manual**: Support manual deployments with environment selection

## Verification and Rollback Strategy

### Deployment Verification
1. **Infrastructure Validation**
   - `azd infra validate` in CI pipeline
   - Resource existence and configuration checks
   - Network connectivity verification

2. **Application Health Checks**
   - Container Apps health endpoint verification
   - Database connectivity tests
   - Application insights telemetry validation

3. **Integration Testing**
   - API endpoint testing
   - Database operation validation
   - MCP protocol functionality verification

### Rollback Procedures
1. **Application Rollback**
   - Revert to previous container image tag
   - Use Container Apps revision management
   - Database migration rollback scripts

2. **Infrastructure Rollback**
   - Git revert of infrastructure changes
   - Re-run deployment with previous version
   - Manual intervention for breaking changes

## Risk Mitigation

### Infrastructure Risks
- **Resource Naming Conflicts**: Use unique suffixes with `uniqueString()`
- **Service Limits**: Monitor quotas and implement request increases
- **Region Availability**: Multi-region deployment option for DR

### Application Risks
- **Database Migration Failures**: Implement backup and rollback procedures
- **Container Startup Issues**: Health check configuration and retry policies
- **Performance Degradation**: Auto-scaling rules and monitoring alerts

### Security Risks
- **Credential Exposure**: Exclusive use of managed identities
- **Network Breaches**: Private endpoints and network segmentation
- **Unauthorized Access**: RBAC and Key Vault access policies
