# Infrastructure as Code and CI/CD Implementation Plan

## Scope

- Provision Azure resources with Bicep: Resource Group (by workflow), Log Analytics, Application Insights, ACR, Key Vault, Azure Database for PostgreSQL Flexible Server, ACA Environment, Container App, Role assignments.
- CI/CD with GitHub Actions using OIDC; build, push, and deploy to ACA.

## Resource model and order

1. Log Analytics Workspace (LAW)
2. Application Insights (classic app connected to LAW)
3. Azure Container Registry (ACR)
4. Key Vault (enable RBAC)
5. PostgreSQL Flexible Server (+ firewall public access, dev-friendly)
6. ACA Managed Environment (logs to LAW)
7. Container App (system-assigned MI, ingress external on :8080)
8. Role assignments: Container App MI → AcrPull on ACR, Key Vault Secrets User on KV
9. KV Secret: `DefaultConnection` (PostgreSQL connection string)

Notes:

- Bicep outputs used to wire cross-resource references (ids, login servers, fqdn).
- Idempotent: modules use `existing` where appropriate; no deletes. Parameters control names/skus.

## Parameters

- `location`, `namePrefix`, `environment` (dev/test/prod)
- ACR SKU, Postgres SKU/vCores/storage/version, ACA env name, app name
- DB admin user (stored as secure param via .bicepparam or injected secret outside of repo)

## Secrets strategy

- Use Key Vault for `DefaultConnection` secret.
- Container App references Key Vault secret via Key Vault reference; uses system-assigned MI.
- Workflow sets/updates the KV secret using AZ CLI after DB is provisioned.

## CI/CD workflow

- Triggers: push to main and PRs; manual dispatch with parameters for resource group, location, env.
- Jobs:
  1) infra: Login with OIDC; ensure resource group; `az deployment group create` with `infra/main.bicep` and env params; capture outputs.
  2) build_push: Build Docker image; tag `${{ github.sha }}`; login to ACR (via az acr login); push.
  3) app_deploy: Update Container App image to new tag; set secrets (Key Vault values already referenced; only ensure secret exists/updated). If app not exists, initial deploy handled by Bicep.
- Uses artifacts/env vars to pass ACR name, image tag, container app name.

## Edge cases

- First run: Container App exists but secret missing: workflow creates Key Vault secret and restarts app.
- Re-run: Idempotent—Bicep updates; secrets updated in place; image tag unique per commit.
- Network: If private Postgres required later, extend with VNet, private DNS, and restricted ingress.

## Success criteria

- Resources created; app deployed to ACA; external URL returns 200 at `/health`.
- App uses Postgres connection string from Key Vault.
- Logs available in Application Insights/Log Analytics.
