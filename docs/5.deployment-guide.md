# Azure Infrastructure Deployment Guide

This guide provides step-by-step instructions for deploying the TodoList application to Azure using Infrastructure as Code (Terraform) and CI/CD (GitHub Actions).

## Prerequisites

Before beginning the deployment, ensure you have:

1. **Azure Subscription**: Active Azure subscription with appropriate permissions
2. **GitHub Repository**: Forked or cloned repository with the TodoList code
3. **Local Development Tools** (for manual deployment):
   - Azure CLI (`az --version`)
   - Terraform (`terraform --version`)
   - Docker (`docker --version`)
   - GitHub CLI (`gh --version`) - optional

## Quick Start (Automated Deployment)

### 1. Configure Azure OIDC Authentication

Follow the [Azure OIDC Setup Instructions](./4.secrets-and-config.md#azure-oidc-setup-instructions) to configure GitHub Actions authentication.

### 2. Set GitHub Repository Secrets

Navigate to your GitHub repository and add the following secrets:

```
Settings > Secrets and variables > Actions > Repository secrets
```

Required secrets:
- `AZURE_CLIENT_ID`: Your Azure AD App Registration Client ID
- `AZURE_TENANT_ID`: Your Azure AD Tenant ID  
- `AZURE_SUBSCRIPTION_ID`: Your Azure Subscription ID

### 3. Deploy via GitHub Actions

#### Option A: Push to Main Branch
```bash
git add .
git commit -m "feat: initial Azure infrastructure deployment"
git push origin main
```

#### Option B: Manual Workflow Dispatch
1. Go to `Actions` tab in your GitHub repository
2. Select `Build and Deploy TodoList Application` workflow
3. Click `Run workflow`
4. Select environment (`dev`, `staging`, `prod`)
5. Click `Run workflow`

### 4. Monitor Deployment

Watch the deployment progress in the Actions tab. The workflow includes:
- **Build**: Compile application and build Docker image
- **Infrastructure**: Deploy Azure resources via Terraform
- **Deploy**: Deploy application to Container Apps
- **Verify**: Run health checks and smoke tests

## Manual Deployment (Advanced)

### 1. Clone Repository

```bash
git clone https://github.com/YOUR_USERNAME/TodoList.git
cd TodoList
```

### 2. Configure Azure CLI

```bash
# Login to Azure
az login

# Set subscription
az account set --subscription "YOUR_SUBSCRIPTION_ID"

# Verify current subscription
az account show
```

### 3. Initialize Terraform

```bash
cd infra

# Initialize Terraform
terraform init

# Create workspace for environment
terraform workspace new dev  # or staging/prod
```

### 4. Configure Variables

Create a `terraform.tfvars` file:

```hcl
# Copy from terraform.tfvars.example and customize
app_name    = "todolist"
environment = "dev"
location    = "East US 2"

# Database configuration
postgresql_sku_name = "B_Standard_B1ms"
storage_mb         = 32768

# Container configuration
container_cpu    = 0.25
container_memory = "0.5Gi"
min_replicas     = 1
max_replicas     = 5

# Security settings
enable_private_endpoint = true
enable_high_availability = false
```

### 5. Plan and Apply Infrastructure

```bash
# Validate configuration
terraform validate

# Plan deployment
terraform plan -var-file="terraform.tfvars"

# Apply changes
terraform apply -var-file="terraform.tfvars"
```

### 6. Build and Push Container Image

```bash
# Get ACR login server from Terraform output
ACR_LOGIN_SERVER=$(terraform output -raw container_registry_login_server)

# Login to ACR
az acr login --name $ACR_LOGIN_SERVER

# Build and push image
cd ..
docker build -t $ACR_LOGIN_SERVER/todolist:latest .
docker push $ACR_LOGIN_SERVER/todolist:latest
```

### 7. Update Container App

```bash
cd infra

# Update container app with new image
terraform apply -var="container_image=$ACR_LOGIN_SERVER/todolist:latest" -var-file="terraform.tfvars"
```

## Environment-Specific Configurations

### Development Environment

```hcl
# terraform.tfvars for dev
environment = "dev"
location    = "East US 2"

# Minimal resources for cost optimization
postgresql_sku_name     = "B_Standard_B1ms"
storage_mb             = 32768
enable_high_availability = false
enable_zone_redundancy = false

# Container settings
container_cpu    = 0.25
container_memory = "0.5Gi"
min_replicas     = 1
max_replicas     = 3

# Security (private endpoints optional for dev)
enable_private_endpoint = false
```

### Staging Environment

```hcl
# terraform.tfvars for staging  
environment = "staging"
location    = "East US 2"

# Balanced resources for testing
postgresql_sku_name     = "GP_Standard_D2s_v3"
storage_mb             = 65536
enable_high_availability = true
enable_zone_redundancy = true

# Container settings
container_cpu    = 0.5
container_memory = "1Gi"
min_replicas     = 1
max_replicas     = 10

# Enhanced security
enable_private_endpoint = true
```

### Production Environment

```hcl
# terraform.tfvars for prod
environment = "prod"
location    = "East US 2"

# Production-ready resources
postgresql_sku_name     = "GP_Standard_D4s_v3"
storage_mb             = 131072
enable_high_availability = true
enable_zone_redundancy = true
geo_redundant_backup_enabled = true

# Auto-scaling configuration
container_cpu    = 1.0
container_memory = "2Gi"
min_replicas     = 2
max_replicas     = 20

# Full security
enable_private_endpoint = true
container_registry_sku = "Premium"
```

### 3. Configure Monitoring

```bash
# Application Insights is automatically configured
# View metrics in Azure Portal > Application Insights

# Set up alerting rules
az monitor metrics alert create \
  --name "TodoList High Response Time" \
  --resource-group rg-todolist-prod-eastus2 \
  --scopes $(terraform output -raw container_app_id) \
  --condition "avg requests/duration > 1000" \
  --description "Alert when average response time exceeds 1 second"
```

## Scaling and Performance

### Horizontal Scaling

The application automatically scales based on:
- HTTP request rate
- CPU utilization
- Memory usage

Scaling is configured in the Terraform variables:
```hcl
min_replicas = 2      # Minimum instances
max_replicas = 20     # Maximum instances
```

### Vertical Scaling

Update container resources:
```hcl
container_cpu    = 2.0    # Increase CPU
container_memory = "4Gi"  # Increase memory
```

### Database Scaling

```bash
# Scale up PostgreSQL
az postgres flexible-server update \
  --resource-group rg-todolist-prod-eastus2 \
  --name psql-todolist-prod-eastus2 \
  --sku-name GP_Standard_D8s_v3
```

## Backup and Recovery

### Database Backups

- **Automated**: PostgreSQL Flexible Server provides automatic backups
- **Retention**: 7-35 days (configurable)
- **Geo-redundant**: Enabled for production

### Application State

- **Stateless Design**: Application doesn't store local state
- **Configuration**: All configuration in Azure Key Vault
- **Secrets**: Managed through Key Vault and Terraform state

### Infrastructure State

- **Terraform State**: Stored in Azure Storage Account
- **State Locking**: Prevents concurrent modifications
- **Versioning**: Enabled on storage account

## Security Best Practices

### Network Security

- ✅ Private endpoints for all Azure services
- ✅ Network Security Groups with restrictive rules
- ✅ Virtual Network integration
- ✅ No public database access

### Identity and Access

- ✅ Managed Identity for service authentication
- ✅ Azure Key Vault for secrets management
- ✅ RBAC with least privilege
- ✅ Regular credential rotation

### Data Protection

- ✅ TLS 1.2+ for all communications
- ✅ Encryption at rest for all storage
- ✅ Encrypted backups
- ✅ Secrets never in plain text

## Troubleshooting

### Common Issues

1. **Container App Won't Start**
   ```bash
   # Check container logs
   az containerapp logs show \
     --name ca-todolist-dev-eastus2 \
     --resource-group rg-todolist-dev-eastus2
   ```

2. **Database Connection Issues**
   ```bash
   # Test database connectivity
   az postgres flexible-server connect \
     --name psql-todolist-dev-eastus2 \
     --admin-user psqladmin
   ```

3. **Terraform State Issues**
   ```bash
   # Import existing resources if state is out of sync
   terraform import azurerm_resource_group.main /subscriptions/SUB_ID/resourceGroups/rg-todolist-dev-eastus2
   ```

4. **GitHub Actions Failures**
   - Check repository secrets configuration
   - Verify OIDC federated credentials
   - Review workflow logs for specific errors

## Cost Optimization

### Development Environment
- Use Basic tier for PostgreSQL
- Disable high availability
- Use minimal container resources
- Scale down to 0 replicas when not in use

### Production Monitoring
- Set up budget alerts
- Monitor unused resources
- Use Azure Cost Management
- Consider reserved instances for long-term deployments

### Resource Lifecycle
```bash
# Destroy non-production environments when not needed
terraform workspace select dev
terraform destroy -var-file="terraform.tfvars"
```
